# Chat Module

## Overview

The chat module allows you to interact with and modify users chat feeds.

- Adds the ability to simulate live updating messages
    - Grants the ability to remove specific messages for a player
- Display clickable chat buttons in a fixed-size box between the chat input field and the chat log.
  - Ability to mix adventure components and icons inside a single button.
  - Ability to customize the button shape, size, position, colors and hover colors.
  - Ability to run commands, open URLs or select a chat tab on click.
- Add server tabs to the chat next to the client tabs, or replace the client tabs with yours.
  - Ability to sort chat messages into a tab with regex, contains or starts with patterns.
  - Ability to send a message straight into a tab.
  - Ability to prefix what players type in a tab, for example with a channel command.
  - Ability to mix adventure components, icons and live parts in a tab name, with a tooltip and a background color.
- Display popups with up to 3 options, for prompts like friend, party or duel requests.
  - Ability to run an action when the player picks an option.
  - Ability to handle the option that the player picked, or why the popup closed, with an event.

### Displaying a Live Chat Message

<Callout type="warning" emoji="⚠️">
  Displaying a message with the same id replaces the previous message. Messages in [chat tabs](#chat-tabs) share these
  ids, and `-1` must not be used, because the client uses it internally.
</Callout>

```java
public void displayLiveChatMessageExample() {
    if (ServerUtil.isFolia()) {
        this.runFoliaChatMessageTask();
    } else {
        this.runBukkitChatMessageTask();
    }
}

private void runBukkitChatMessageTask() {
    BukkitRunnable runnable = new BukkitRunnable() {

        private int countdown = 5;

        @Override
        public void run() {
            if (this.countdown > 0) {
                ChatApiExample.this.chatModule.displayLiveChatMessage(Recipients.ofEveryone(),
                    Component.text("Game starting in ", NamedTextColor.GREEN)
                        .append(Component.text(this.countdown, NamedTextColor.BLUE)),
                    13
                );

                this.countdown--;
            } else {
                ChatApiExample.this.chatModule.displayLiveChatMessage(Recipients.ofEveryone(),
                    Component.text("Game started! ", NamedTextColor.GREEN),
                    13
                );

                this.cancel();
            }
        }
    };

    runnable.runTaskTimer(ApolloExamplePlugin.getInstance(), 1L, 20L);
}

private void runFoliaChatMessageTask() {
    AtomicInteger countdown = new AtomicInteger(5);

    Bukkit.getGlobalRegionScheduler().runAtFixedRate(ApolloExamplePlugin.getInstance(), task -> {
        int seconds = countdown.getAndDecrement();
        if (seconds > 0) {
            ChatApiExample.this.chatModule.displayLiveChatMessage(Recipients.ofEveryone(),
                Component.text("Game starting in ", NamedTextColor.GREEN)
                    .append(Component.text(seconds, NamedTextColor.BLUE)),
                13
            );
        } else {
            ChatApiExample.this.chatModule.displayLiveChatMessage(Recipients.ofEveryone(),
                Component.text("Game started! ", NamedTextColor.GREEN),
                13
            );

            task.cancel();
        }
    }, 1L, 20L);
}
```

## Chat Buttons

Display server-driven clickable buttons on the chat screen. Buttons live in a single invisible fixed-size box
(`320x20` GUI-scaled pixels) anchored in the strip between the chat input field and the chat log, visible while the chat screen is open.

Chat buttons are built on Apollo's shared button system: `ChatButton` extends `ApolloButton`.
Read the [buttons utilities page](/apollo/developers/utilities/buttons) for the shared
concepts: content, tooltips, click actions, shapes, sizes, colors and the update semantics.

  Displaying buttons with the same id replaces the previous button.

### Live Chat Buttons

Content parts and tooltips can be **live**: instead of a static value, you provide a resolver that is called
for each viewing player and re-broadcast automatically by the module (see [Live Button Broadcast](#live-button-broadcast) below).

```java
public void displayLiveChatButtonExample(Player viewer) {
    Optional<ApolloPlayer> apolloPlayerOpt = Apollo.getPlayerManager().getPlayer(viewer.getUniqueId());

    apolloPlayerOpt.ifPresent(apolloPlayer -> {
        ChatButton unread = ChatButton.builder()
            .id("unread")
            .position(HudPosition.of(0, 2))
            .size(ChatButton.SIZE_MEDIUM)
            .shape(ApolloButtonShape.ROUNDED_SQUARE)
            .backgroundColor(ChatButton.DEFAULT_BACKGROUND_COLOR)
            .borderColor(ChatButton.DEFAULT_BORDER_COLOR)
            .content(ApolloButtonContent.builder()
                .append(Component.text("Unread: ", NamedTextColor.GRAY))
                .append(apolloViewer -> Component.text(getUnreadCount(apolloViewer.getUniqueId()), NamedTextColor.RED), Duration.ofSeconds(1))
                .scale(0.85F)
                .build())
            .build();

        this.chatModule.displayChatButton(apolloPlayer, unread);
    });
}
```

### `ChatButton` Options

`ChatButton` extends `ApolloButton`. All shared options: `.id(...)`, `.shape(...)`, `.backgroundColor(...)` & `.borderColor(...)`,
`.content(...)`, `.tooltip(...)`, `.onClick(...)` and the hovered color overrides are documented on the [buttons utilities page](/apollo/developers/utilities/buttons),
along with the `ApolloButtonContent`, `ApolloButtonTooltip` and `ApolloButtonAction` builders used above.

`.position(HudPosition)` the button position, in GUI-scaled pixels. The button must fit inside the `320x20` box (`ChatButton.BOX_WIDTH` x `ChatButton.BOX_HEIGHT`), so `x + width <= 320` and `y + height <= 20`.
```java
.position(HudPosition.of(0, 2))
```

`.size(ApolloButtonSize)` the button size, in GUI-scaled pixels. Use one of the suggested chat sizes:
`ChatButton.SIZE_SMALL` (56x16, five fit side by side), `SIZE_MEDIUM` (96x16, three fit side by side) or
`SIZE_ICON` (16x16, for square icon-only buttons) or a fully custom size via `ApolloButtonSize.of(width, height)`.
```java
.size(ChatButton.SIZE_MEDIUM)
.size(ApolloButtonSize.of(56, 16))
```

## Live Button Broadcast

Chat buttons displayed through the Apollo API with live content parts or a live tooltip are automatically resent while the `buttons.live-broadcast` option is enabled (disabled by default); no
scheduler code required. The broadcast engine ticks every server tick (50ms) and
sends each live piece whenever its own update interval elapses, refreshing content and tooltip independently.

Every live part and live tooltip carries its own update interval, set through the content builder's
`append(resolver, Duration)` (or `ApolloButtonContentPart.live(resolver, Duration)`) and `ApolloButtonTooltip.live(resolver, Duration)`.
Lightweight integrations replicate this by re-sending `UpdateChatButtonMessage` from their own repeating task.
Chat tabs have their own option, see [Live Tab Broadcast](#live-tab-broadcast).

<Callout type="info">
  With only `buttons.live-broadcast` enabled, updates are always sent to **every** player holding live
  buttons, even while their chat is closed. Also enable the packet enrichment module and its player chat
  open/close packets and events. Apollo then only sends updates to players who currently have their chat
  open, and pushes fresh values the moment the chat is opened.
</Callout>

```diff
  modules:
    chat:
      enable: true
      buttons:
-       live-broadcast: false
+       live-broadcast: true
    packet_enrichment:
-     enable: false
+     enable: true
      player-chat-open:
-       send-packet: false
+       send-packet: true
-       fire-apollo-event: false
+       fire-apollo-event: true
      player-chat-close:
-       send-packet: false
+       send-packet: true
-       fire-apollo-event: false
+       fire-apollo-event: true
```

## Default Buttons

Chat buttons can be defined directly in `config.yml` and displayed automatically when a player joins, without any
plugin code. Set `buttons.send-defaults` to `true` (it is `false` by default) and define the buttons under `buttons.defaults`.

Config buttons are **static**: text is read as legacy strings (`&`-color codes) and icons as icon
definitions. Live content parts and live tooltips require a resolver and are therefore only available
through the API.

```yaml
modules:
  chat:
    buttons:
      send-defaults: true
      defaults:
      - id: team-chat
        position:
          x: 0.0
          y: 2.0
        size:
          width: 70.0
          height: 16.0
        shape: ROUNDED_SQUARE          # ROUNDED_SQUARE or CIRCLE
        background-color: '#80000000'  # '#RRGGBB' or '#AARRGGBB'
        border-color: '#80000000'
        content:
          scale: 1.0
          parts:                       # each part is a 'text' or an 'icon'
          - icon:
              name: SHIELD
          - text: '&aTeam Chat'
        tooltip:
        - '&eClick to switch!'
        on-click:                      # one of run-command, open-url, client-action or select-chat-tab
          run-command: /channel team
```

## Chat Tabs

Lunar Client shows a tab bar above the chat input while the chat is open. The "All" tab shows the whole chat. Next to
it are two kinds of tabs:

- **Client tabs** are the tabs that Lunar Client adds itself, like party and private messages.
- **Server tabs** are the tabs that your server adds through this module, with the API or with `tabs.defaults` in
  the config.

Server tabs are added next to the client tabs, unless `tabs.replace-client-tabs` is enabled, which hides every client
tab except "All". Tabs that the player made themselves stay either way.

There are two ways for a message to get into a server tab, and they differ in whether the message also shows in "All":

- **Patterns.** The client puts a chat message into your tab when one of the tab's patterns matches the message's plain
  text, without formatting codes. The message still shows in "All" too, unless the tab has `hideFromAll` set. A pattern
  is a `TextPattern.regex(...)`, `TextPattern.contains(...)` or `TextPattern.startsWith(...)`, and ignores the case of
  the letters unless you call `.withCaseSensitive(true)` on it.
- **`displayChatTabMessage`.** The message goes straight into the tab, without matching any pattern, and never shows
  in "All". A tab without patterns only gets these messages. It works like a live chat message: the same message id
  updates the message, and `removeLiveChatMessage` removes it. A player whose client doesn't have the tab, who turned
  chat tabs off, or whose client is from before chat tabs sees the message in their normal chat instead.

Tabs stay while the player switches between the servers behind a proxy, and are removed when the player disconnects.
Apollo also runs on Velocity and BungeeCord, and when it runs on the proxy, it keeps track of the tabs across these
switches. When Apollo runs on the backend servers instead, each backend server only knows the tabs that it displayed
itself, so the 16 tab limit doesn't count the tabs that another backend server displayed.

<Callout type="info">
  Displaying a tab with the same id replaces the previous tab. A player can have at most 16 server tabs at the same
  time, in total across every display call (`ChatTab.MAX_TABS`). Apollo skips the players that a display would take
  over that with a warning, and throws when the call was for one player.
</Callout>

<Callout type="warning" emoji="⚠️">
  These limits apply to every integration. A player can have at most 16 server tabs at the same time
  (`ChatTab.MAX_TABS`), and a tab can have up to 16 patterns (`ChatTab.MAX_PATTERNS`) of up to 256 characters each
  (`ChatTab.MAX_PATTERN_LENGTH`). The client cuts off a tab name longer than 32 characters
  (`ChatTab.MAX_DISPLAY_NAME_LENGTH`). Only the visible characters of the text parts count, formatting codes don't,
  and the client never cuts inside a formatting code.
</Callout>

<Callout type="warning" emoji="⚠️">
  Tab messages are live chat messages, so they share their message ids with `displayLiveChatMessage`. Don't use `-1`,
  because the client uses it internally.
</Callout>

### `ChatTab` Options

`.id(String)` is the tab id that the other methods refer to. It must not be `all`, because `selectChatTab("all")`
selects the "All" tab.
```java
.id("staff")
```

`.displayName(ApolloButtonContent)` is the name on the tab, built like the content of a chat button, with text, icons
and live parts. Live parts are re-sent while `tabs.live-broadcast` is enabled, see [Live Tab Broadcast](#live-tab-broadcast).
The client ignores the scale, because the tabs have the height of a chat line.
```java
.displayName(ApolloButtonContent.builder()
    .append(Component.text("Staff", NamedTextColor.RED))
    .build())
```

`.tooltip(ApolloButtonTooltip)` is shown while the tab is hovered. Leave it out for no tooltip.
```java
.tooltip(ApolloButtonTooltip.of(Component.text("Server events", NamedTextColor.YELLOW)))
```

`.backgroundColor(Color)` is the background of the tab. Leave it out for the background of the chat input field.
```java
.backgroundColor(new Color(64, 32, 0, 160))
```

`.patterns(List<TextPattern>)` sorts the chat messages that one of the patterns matches into the tab. A tab can have
up to 16 patterns (`ChatTab.MAX_PATTERNS`) of up to 256 characters each (`ChatTab.MAX_PATTERN_LENGTH`), and a pattern
must not be empty, because an empty pattern matches every message. When a regex takes too long on a message, the client
skips that pattern for the message, so keep regexes simple.
```java
.patterns(Arrays.asList(
    TextPattern.startsWith("[Staff] ").withCaseSensitive(true),
    TextPattern.contains("joined the queue"),
    TextPattern.regex("^\\[(Admin|Mod)\\] ")
))
```

`.inputPrefix(String)` is put in front of every message that a player sends while the tab is open. For example, with
`/staffchat `, typing `hi` in the tab sends `/staffchat hi`. It only changes what the player sends, the patterns decide
which messages go into the tab. Commands are sent unchanged. Leave it empty to send messages unchanged. A prefix that
starts with `/` is a command, so the client puts a space after it when it doesn't end with one. Other prefixes like `!`
are put right in front of the message.
```java
.inputPrefix("/staffchat ")
```

`.hideFromAll(boolean)` shows the tab's messages only in the tab, and not in the "All" tab.
```java
.hideFromAll(true)
```

## Live Tab Broadcast

Chat tabs displayed through the Apollo API with live parts in the display name or a live tooltip are automatically
resent while the `tabs.live-broadcast` option is enabled (disabled by default). It works like
[Live Button Broadcast](#live-button-broadcast), with its own option, so live tabs and live chat buttons are turned on
separately. Lightweight integrations replicate this by re-sending `UpdateChatTabMessage` from their own repeating task.

<Callout type="info">
  Unlike live buttons, live tabs get updates even while the player's chat is closed, also with the packet enrichment
  chat open/close tracking enabled, because the client shows the name of the selected tab outside the open chat too.
</Callout>

```diff
  modules:
    chat:
      enable: true
      tabs:
-       live-broadcast: false
+       live-broadcast: true
```

## Default Tabs

Chat tabs can also be defined in `config.yml` and displayed when a player joins, without any plugin code. Set
`tabs.send-defaults` to `true` (it is `false` by default) and define the tabs under `tabs.defaults`. `send-defaults`
only controls this list, tabs that a plugin displays through the API are sent either way.

Config tabs are **static**: text is read as legacy strings (`&`-color codes) and icons as icon definitions. Live parts
in the display name and live tooltips are only available through the API.

The `display-name` is either a legacy string, or content with `parts` in the same format as the content of
[Default Buttons](#default-buttons). The client ignores `scale` for tabs, because tabs have the height of a chat line.

```yaml
modules:
  chat:
    tabs:
      replace-client-tabs: false
      live-broadcast: false
      send-defaults: true
      defaults:
      - id: team
        display-name: '&aTeam'
        tooltip:                       # optional
        - '&7Your team chat'
        background-color: '#80003300'  # optional, '#RRGGBB' or '#AARRGGBB'
        patterns:                      # each has exactly one of regex, contains or starts-with
        - starts-with: '[Team] '
          case-sensitive: true         # optional, false by default
        input-prefix: '/tc '
        hide-from-all: false
      - id: staff
        display-name:
          parts:                       # each part is a 'text' or an 'icon'
          - icon:
              name: SHIELD
          - text: '&cStaff'
        patterns:
        - starts-with: '[Staff] '
        input-prefix: '/sc '
        hide-from-all: true
```

## Chat Popups

Chat popups are notification style popups with up to 3 options that the player can pick, for prompts like friend, party
or duel requests.

When a popup closes, the client sends a response to the server, which Apollo posts as an `ApolloChatPopupResponseEvent`,
so your plugin handles the answer in the event. Its status tells why the popup closed:

- `PICKED`: the player picked the option with the event's option id. The option id is null for every other status.
  An option with a run command or open URL action only counts as picked once its command runs or its URL opens, after
  the player confirms the prompt. A client action or a select chat tab action counts as picked right away, even when
  it has nothing to do, for example because the tab doesn't exist.
  The player can also answer a popup by sending an option's run command themselves, for example by clicking a message
  in chat. That closes every popup with an option that has that command, and sends `PICKED` for each of them.
- `DISMISSED`: the player closed the popup without picking an option, or picked an option whose action didn't happen:
  they cancelled its prompt, or its URL couldn't open because the player turned off chat links or the URL is invalid.
- `EXPIRED`: the popup's display time ran out.
- `DROPPED`: the client threw the popup away without showing it, because it had too many popups.

<Callout type="warning" emoji="⚠️">
An option whose run command is a command your plugin handles itself, like `/duel accept`, reaches your plugin twice:
once as the command and once as a `PICKED` response. Handle the answer in only one of the two places.
</Callout>

No response is sent when the server removes the popup, or for the popups that are still displayed when the player
disconnects. Popups stay when the player changes worlds or dimensions or switches between the servers behind a proxy,
and are removed when the player disconnects. Lunar Client versions from before chat popups don't show them, and no response is sent for them then, so don't
rely on getting a response for every popup. Apollo popups are shown even to players who turned the client's own chat
popups off.

Apollo keeps track of the popups that it displayed to each player, and only posts the event for a popup that is still
displayed to that player, and for a `PICKED` response only when the option id is one of the popup's options. The event
carries the `ChatPopup` that was displayed. The client keeps up to 20 popups (`ChatPopup.MAX_POPUPS`), which includes
its own popups for servers like Hypixel, and responds
with `DROPPED` for each popup it drops past that, so Apollo's tracking stays in step. Apollo only forgets popups on its
own past 64 per player, for clients that never respond. When Apollo runs on the backend servers
behind a proxy instead of on the proxy, a response to a popup that another backend server displayed doesn't post the
event, because the response goes to the server that the player is on now.

<Callout type="warning" emoji="⚠️">
  Use a new popup id for each request, for example with a random UUID. Displaying a popup with the same id replaces the
  previous popup, and when an answer to the previous popup is still on its way, that answer is attributed to the newer
  popup.
</Callout>

<Callout type="warning" emoji="⚠️">
  These limits apply to every integration. A popup can have up to 3 options (`ChatPopup.MAX_OPTIONS`). The client cuts
  off a title longer than 128 characters (`ChatPopup.MAX_TITLE_LENGTH`), a description longer than 512 characters
  (`ChatPopup.MAX_DESCRIPTION_LENGTH`) and an option label longer than 64 characters
  (`ChatPopupOption.MAX_LABEL_LENGTH`). Only the visible characters count, formatting codes don't, and the client never
  cuts inside a formatting code.
</Callout>

### Displaying a Chat Popup

The example keeps the id of each player's last duel request, so that it can remove the popup again.

```java
private final Map<UUID, String> duelRequestIds = new ConcurrentHashMap<>();

public void displayChatPopupExample(Player viewer) {
    Optional<ApolloPlayer> apolloPlayerOpt = Apollo.getPlayerManager().getPlayer(viewer.getUniqueId());

    apolloPlayerOpt.ifPresent(apolloPlayer -> {
        String popupId = "duel-request-" + UUID.randomUUID();
        this.duelRequestIds.put(viewer.getUniqueId(), popupId);

        this.chatModule.displayChatPopup(apolloPlayer, ChatPopup.builder()
            .id(popupId)
            .title(Component.text("Duel Request"))
            .description(Component.text("Steve wants to duel you."))
            .displayTime(Duration.ofSeconds(60))
            .options(Arrays.asList(
                ChatPopupOption.builder()
                    .id("accept")
                    .label(Component.text("Accept", NamedTextColor.GREEN))
                    .onClick(ApolloButtonAction.runCommand("/duel accept Steve"))
                    .build(),
                ChatPopupOption.builder()
                    .id("deny")
                    .label(Component.text("Deny", NamedTextColor.RED))
                    .build(),
                ChatPopupOption.builder()
                    .id("reply")
                    .label(Component.text("Reply", NamedTextColor.GRAY))
                    .onClick(ApolloButtonAction.selectChatTab(SelectChatTabAction.ALL_TAB_ID, true))
                    .build()
            ))
            .build()
        );
    });
}
```

### Handling Chat Popup Responses

Listen to the `ApolloChatPopupResponseEvent`, see [Events](/apollo/developers/events) for how to register a listener.

```java
@Listen
private void onChatPopupResponse(ApolloChatPopupResponseEvent event) {
    Player player = (Player) event.getPlayer().getPlayer();
    String popupId = event.getPopupId();
    this.duelRequestIds.remove(player.getUniqueId(), popupId);

    switch (event.getStatus()) {
        case PICKED: {
            player.sendMessage("You picked " + event.getOptionId() + " on the " + popupId + " popup.");
            break;
        }

        case DISMISSED: {
            player.sendMessage("You closed the " + popupId + " popup.");
            break;
        }

        case EXPIRED: {
            player.sendMessage("The " + popupId + " popup expired.");
            break;
        }

        case DROPPED: {
            player.sendMessage("The " + popupId + " popup was dropped, because you had too many popups.");
            break;
        }
    }
}
```

### `ChatPopup` Options

`.id(String)` is the popup id that the other methods and the response refer to.
```java
.id("duel-request-" + UUID.randomUUID())
```

`.title(Component)` is the title of the popup.
```java
.title(Component.text("Duel Request"))
```

`.description(Component)` is the text below the title. Leave it out for a popup without a description.
```java
.description(Component.text("Steve wants to duel you."))
```

`.displayTime(Duration)` is how long the popup stays, usually the time until the request that it asks about expires.
Leave it out to keep the popup until the player closes it or the server removes it.
```java
.displayTime(Duration.ofSeconds(60))
```

`.options(List<ChatPopupOption>)` sets up to 3 options (`ChatPopup.MAX_OPTIONS`), and the client draws them as buttons
in this order.
```java
.options(Arrays.asList(accept, deny))
```

### `ChatPopupOption` Options

`.id(String)` is the option id that the response carries.
```java
.id("accept")
```

`.label(Component)` is the text on the option's button.
```java
.label(Component.text("Accept", NamedTextColor.GREEN))
```

`.onClick(ApolloButtonAction)` runs when the player picks the option, before the client sends the response. It takes
the same actions as a button, see the [buttons utilities page](/apollo/developers/utilities/buttons#apollobuttonaction).
The client asks the player before it runs a command or opens a URL, like it does for buttons. The response is only
`PICKED` once the command runs or the URL opens, and cancelling the prompt sends `DISMISSED`. Leave it out to only send
the response.
```java
.onClick(ApolloButtonAction.runCommand("/duel accept Steve"))
.onClick(ApolloButtonAction.selectChatTab(SelectChatTabAction.ALL_TAB_ID, true))
```

## Available options

- __`BROADCAST_LIVE_BUTTONS`__
    - Whether live chat button content is automatically re-resolved and re-sent to viewers.
    - Values
        - Type: `Boolean`
        - Default: `false`

- __`SEND_DEFAULT_BUTTONS`__
    - Whether the default buttons are displayed to players when they join.
    - Values
        - Type: `Boolean`
        - Default: `false`

- __`DEFAULT_BUTTONS`__
    - The default buttons displayed to joining players while `buttons.send-defaults` is enabled.
    - Values
        - Type: `List<ChatButton>`
        - Default: `chat-channels sample buttons`

- __`REPLACE_CLIENT_TABS`__
    - Whether the server tabs replace the client tabs, except the "All" tab.
    - Values
        - Type: `Boolean`
        - Default: `false`

- __`BROADCAST_LIVE_TABS`__
    - Whether live chat tab display names and tooltips are automatically re-resolved and re-sent to viewers.
    - Values
        - Type: `Boolean`
        - Default: `false`

- __`SEND_DEFAULT_TABS`__
    - Whether the default tabs are displayed to players when they join.
    - Values
        - Type: `Boolean`
        - Default: `false`

    - The default tabs displayed to joining players while `tabs.send-defaults` is enabled.
    - Values
